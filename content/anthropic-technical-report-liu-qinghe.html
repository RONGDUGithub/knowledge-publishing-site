Slide 07

MCP

缺陷

工具定义膨胀

标准化

：

MCP

要求每个工具定义非常完整、自包含，导致单条定义更长。

全量注入

：当前实践倾向于一次性加载所有工具的完整定义，导致总

tokens

迅速膨胀。

上下文污染

由于MCP客户端通常将所有工具定义、资源描述、提示模板等一次性全量注入模型的上下文窗口，导致大量与当前用户任务无关的信息占据宝贵的上下文空间，不仅浪费

tokens（增加成本），还会干扰模型注意力。

工具选择问题：工具越多，模型越容易选错

大量细粒度工具会把

Agent

的规划问题变成工具选择噪声。

标准化描述模板

：每个工具的描述格式相似，缺乏权重区分（例如“常用工具”没有被标记）

无工具优先级机制

：模型无法知道哪个工具更通用、哪个更专用，只能平等对待。

全量工具注入

：模型被迫一次性看到所有工具，无法“先看摘要再选细节”

Tool Search

不要把所有工具定义一次性塞进上下文，而是

暴露一个“搜索工具”的工具，

让模型先搜索工具目录，再按需加载相关工具。

测试数据：工具定义的 token 消耗减少了 85% 以上，工具选择的准确率没有下降。

Slide 10

Programmatic Tool Calling

传统 tool use 是：模型调用一个工具，结果进入上下文；模型再读结果，再调用下一个工具；如此循环。

产生两个问题：中间结果污染上下文 + 每一步都需要一次完整模型推理

工具返回的结果不再直接丢回给模型，而是在代码执行沙箱里处理。Agent 可以在沙箱里循环、过滤、聚合，只把最终结果返回到上下文

在复杂多步工作流上减少了约 37% 的 token 消耗

代码编排

Cloudflare 的 MCP 服务器，覆盖了大约 2,500 个 API 端点

传统方式：把这 2,500 个端点的工具定义全塞进上下文

Slide 18

Computer Use

是

如何实现的？

它的基本执行流程是一个

agent loop

：

感知—推理—行动循环

第一步：感知屏幕

系统把当前浏览器或桌面的截图传给模型。模型通过视觉能力识别页面结构：按钮在哪里、输入框在哪里、弹窗是什么、当前任务进度如何。

第二步：推理和规划

模型根据用户目标、当前截图、历史动作，决定下一步应该做什么。

第三步：输出动作

Claude

本身不会直接连接电脑环境；

Claude

发出

tool use

请求，把它翻译成真实环境中的动作，开发者的应用在虚拟机或容器中执行这个动作；

第四步：返回新截图，继续循环

动作执行后，系统重新截图并

返回模型。模型判断任务是否完成；如果没完成，就继续下一步。

Slide 19

Computer Use

的难点

至少有三类误差。

一是

感知误差

模型可能没看懂界面，或者小按钮太小，文字太模糊，当前

UI

状态和任务目标不匹配。

二是

执行误差

模型可能知道要点哪个按钮，但坐标偏了；或者页面滚动后目标位置变了；或者弹窗出现后原计划失效。

三是

安全误差

Computer Use Agent

接触的是网页、邮件、截图和真实

UI，

这些内容本身都可能是不可信的，可能包含隐藏文本、操控图像、欺骗性

UI

或社会工程指令，从而诱导

Agent

执行错误行为。

Computer Use

的研究难点不是“让模型会看图”，而是：

如何让视觉-动作闭环在真实

UI

中可靠、可恢复、可审计、可限制。

Slide 20

Anthropic 的最佳实践

想让

AI agent

点得更准，请先把截图缩小。

Claude

的内部有一个

硬性图片分辨率上限，超过了这个限制

:

API

会自动缩小图片。

问题在于：模型看到的是缩小后的截图，返回的坐标也是基于缩小后的尺寸，而客户端还在用原始分辨率去执行点击。

解法：自己先把图片缩小，不要让

API

缩。

不过缩完了之后要记得一件事：坐标要缩放回去。

模型返回的点击坐标是基于你发送的缩小尺寸，执行的时候得乘以缩放系数还原到屏幕真实坐标。

Slide 21

Anthropic 的最佳实践

先说再看

在构造消息时，要记得把文字指令放在图片前面。

原理在于，模型先读到「点击提交按钮」，再看截图，就知道该找什么了。如果先看图再看指令，模型还得回头重新理解图片，准确率会有所下降。

Slide 22

Anthropic 的最佳实践

谁点的准

Sonnet 4.6

的点击精度最高，空间定位准，近距离失误少，而且对图片压缩的容忍度也更好。适合大部分机械执行类任务。

Opus 4.7

的推理能力更强，而且点击精度已经追上了

Sonnet 4.6.

加上它的分辨率预算更大（3.75

MP vs 1.15MP），

需要压缩的幅度也更小。如果任务既需要推理又需要精准点击，

Opus 4.7

是目前的最优解。

Haiku 4.5

则是延迟优先的选择，适合对速度要求极高的场景。

对于复杂工作流，这里还有一个高级模式：用一个推理能力强的模型做「指挥官」负责规划和决策，再让

Sonnet

或

Haiku

去执行具体的点击操作。分工协作，各司其职。

Anthropic 的最佳实践

防御体系

训练层面，模型在训练时就接触过大量含有注入内容的网页和应用界面，通过强化学习学会了识别和拒绝恶意指令。

实时分类器，在每次请求时并行扫描进入

持续红队测试，安全研究人员不断试探防线，

最有效的防御

Slide 24

Anthropic 的最佳实践

教学模式

用户先手动执行一遍任务，系统录制每一步操作，包括点击坐标、输入内容、页面导航，每步都配一张截图，截图上用蓝色圆圈标注了用户点击的位置。

回放的时候，

Claude

收到的是完整的操作示范：「第 1 步，点击费用类型下拉菜单」配一张标注了蓝圈的截图，「第 2 步，选择差旅类型」配下一张截图……

Claude

看着这些示范，在当前真实环境里执行相同的操作序列。

Anthropic

设计了三种回放模式：

•

严格模式

：完全按步骤执行，

UI

变化太大就停下来报告。适合合规敏感的场景

•

自适应模式

：以示范为参考但灵活调整，能应对轻微的布局变化、按钮改名、菜单重排。

•

目标导向模式

：只关注最终结果，录制的步骤只是参考，不是必须遵循的指令。适合

UI

经常变但目标不变的场景
