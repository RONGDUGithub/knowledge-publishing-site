Codex Cheat Sheet

Codex 基础命令速查

按“指令 + 作用 + 适用场景”整理 Codex 常用命令，适合新手入门、日常开发和提交前风险检查。

核心概念 10 条黄金指令 分支管理 初始化流程 避坑提醒

一、核心概念：两种指令的区别

类型 定义 示例
普通 Prompt 让 Codex 执行的具体任务，重点是“做什么”。 帮我修复这个 bug、帮我重构权限系统
斜杠指令 控制 Codex 工作方式的命令，重点是“怎么管理工具”。 /init /plan /diff
关键规则：斜杠指令必须放在输入开头，否则会被当成普通文字；忘记指令时，直接输入 / 可唤起指令列表。

二、10 条黄金指令

/init

初始化项目

作用

生成 AGENTS.md，相当于给 Codex 写“项目入职手册”。

适用场景

首次打开陌生项目、建立项目规则、避免每次重复说明启动方式和代码规范。

建议

生成后手动补充禁止修改目录、依赖版本要求、测试命令等项目专属规范。

/status

查看当前状态

作用

查看模型、权限策略、可写目录和上下文信息。

适用场景

排查权限问题、确认模型切换是否成功、检查是否处于只读模式、对话过长时定位问题。

/model

切换模型

作用

切换当前使用的模型，控制成本与效率。

口诀

简单任务用快模型，复杂任务用强模型，该省省，该花花。

场景

强模型适合大型重构、复杂 bug、架构设计；快模型适合改文案、看函数、修简单类型错误。

/permissions

控制文件权限

作用

控制 Codex 的文件操作权限，例如只读、可修改、执行命令前需确认。

适用场景

生产项目、老项目、无 Git 项目，避免 Codex 无限制修改文件导致风险。

新手建议

初期设为只读，让 Codex 先读项目、出方案、解释原因，熟悉后再逐步放开权限。

/plan

先出方案

作用

让 Codex 分析任务、输出方案，先不修改代码，提前理清需求和风险。

适用场景

重构、技术迁移、复杂 bug、性能优化、多文件修改、不确定风险的任务。

示例

/plan 帮我分析当前权限系统，给出最小风险的重构方案，先不要改代码

/mention

指定目标文件

作用

指定文件、组件或配置，让 Codex 围绕目标分析，避免全项目无差别扫描。

适用场景

已知报错文件、需要分析特定模块、希望节省 Token 和时间。

示例

/mention ~/home/login.swift 后续提问“帮我分析这个文件的登录流程”。

/diff

查看真实改动

作用

查看 Codex 实际修改的文件内容，包括新增、删除和修改。

适用场景

所有修改完成后、提交代码前必须使用，确认改动范围和内容。

建议

搭配 /review 使用，先看改动，再做代码审查。

/review

切换审查视角

作用

检查代码改动是否存在 bug、行为回归、缺测试、边界遗漏或安全风险。

适用场景

提交代码前、Codex 完成修改后，确保改动符合预期且风险可控。

/compact

压缩历史对话

作用

把历史对话压缩为摘要，继续当前任务，缩短上下文长度。

关键说明

不是清空对话，而是保留当前话题的压缩历史；彻底换任务用 /new 或 /clear。

/resume

恢复历史会话

作用

打开历史会话列表，恢复之前中断的任务，或切换回主线会话。

适用场景

跨天任务、长时间 debug、大项目迁移、分阶段开发、/fork 后回到主线。

三、辅助指令：会话分支管理

/fork

复制当前会话

创建一条新的实验分支，类似 Git 分支，不影响主线会话。

适用场景

尝试不同实现方案、对比多种架构、保留主线同时开实验线、让 Codex 用不同思路实现功能。

/side

开启临时侧边对话

问临时问题，不污染主线会话，问完可直接回到主线继续工作。

适用场景

临时询问方案风险、概念解释、简单判断；不适合复杂多轮讨论或长期实验路线。

示例

/side 这个方案有没有明显风险？

四、新项目初始化流程

进入项目目录。
使用 /init 初始化项目说明，生成 AGENTS.md。
使用 /status 查看当前状态，包括模型、权限和目录。
让 Codex 先读项目，理解结构和关键模块。
使用 /plan 输出任务方案，确认风险可控。
确认方案后，再开始修改。
使用 /diff 查看实际改动。
使用 /review 做提交前代码审查。
确认无误后提交代码。

新手避坑关键提醒

  • 权限不要一开始全开，生产项目和老项目优先只读模式。
  • 复杂任务必须先 /plan，不要直接让 Codex 动手改代码。
  • 所有修改完成后，一定用 /diff 看真实改动，不要只看总结。
  • 对话过长时用 /compact，避免上下文无限增长。
  • 临时问题用 /side，多方案尝试用 /fork，避免主线会话被污染。
